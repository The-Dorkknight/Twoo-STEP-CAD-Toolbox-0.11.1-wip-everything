# How Twoo STEP CAD Toolbox works

**WORK IN PROGRESS: MANY FEATURES MAY BE BROKEN** (0.10.2-wip)

## What it reads, changes, and never does
- **Reads:** the mesh, STEP, OpenSCAD file or picture you choose (an OpenSCAD file is also read by OpenSCAD itself, together with any `include` / `use` files it names). **Writes:** new files into `Output/` (and temporary work files into `runtime/tmp`). Your originals are never modified.
- **Network:** the first start downloads `uv`, Python 3.12 and the libraries (from the official sources, into `runtime/`). After that it is fully offline. The app's web page is served only on `127.0.0.1` (your own computer), protected by a random per-session token; nothing is uploaded anywhere and there is no telemetry.
- **Never:** touches your system Python, installs system-wide, edits your CAD files, or sends your models anywhere. The optional Install tab copies a plug-in folder into FreeCAD's / Fusion's user folder (and a menu entry on Linux) only when you click its button.

## Pipeline (Smooth surfaces mode)
Python is only the conductor; the heavy geometry is done by compiled libraries (OpenCASCADE via `cadquery-ocp`, NumPy/SciPy, Shapely; OpenCV for the Image → STEP tab).
1. Load and clean the mesh (triangles turned to agree with their neighbours by `tostep/plugins/mesh2step/meshfix.py`, holes filled); choose a tolerance from the part size.
2. Find flat regions (planes) and sharp-edge creases.
3. Split the rest into smooth components; fit cylinders/spheres (RANSAC) and planes.
4. Lay out the remaining smooth area as patches; trace boundaries and fit curves.
5. Fit a NURBS surface to each patch (least squares; a plate fill when that misses). Since 0.10.0 each fitted or flat face is built and repaired on its **own copy** of the outline (OpenCASCADE's face repair widens outline vertices to make a wire close on a surface that misses them; on a shared outline that widening reached the neighbours and let faces 1.3 mm off pass every check), a face whose repair had to widen the outline by more than twice the tolerance is refused, and the plate filler gets its outline as one chained wire (loose edges were chained through a map hashed on memory addresses, which made the vase's result differ from run to run).
6. Check every face (valid, right area, close to the mesh). Anything that fails falls back to exact triangles so the result is always a **closed solid**. Since 0.10.2 the finished solid is also written, read back and checked the other way round (Classic and Ladder; Staged always did): a region whose own triangle centres or corners are more than three times the tolerance from the result, or a round face OpenCascade can't triangulate when the whole solid is meshed, is rebuilt as exact facets (`cover_check`, `trip_check`). The checks mesh a copy: meshing a shape twice can make OpenCascade's mesher run without end.
7. Join the faces (by their shared edges when every edge is shared, else by sewing), write STEP, re-read it and measure deviation from the mesh.

*Exact facets* keeps every triangle (coplanar ones merged). *Extrude outline* / *Loft* (experimental) redraw a part from 2D outlines.
*Jetwash* finds tiny faces/edges/holes below your threshold and removes them with OpenCASCADE's shape healing, undoing any removal that would damage the part. Candidates go in batches of up to 16 faces while batches succeed, then one at a time (0.10.0: defeaturing costs about 0.3 s a face up to there and far more beyond; a batch of 81 faces that failed cost 38 s).

## Hardpoints tab
`tostep/plugins/mesh2step/hardpoints.py` reads and writes the hardpoint STL format (`tostep/core/hstl.py`, standard library only; format in `HARDPOINT_STL.md`). `inspect()` is what the tab shows when you drop a file: valid labels, labels present but triangles edited since (labels ignored), or a plain STL. In a conversion with labels, each labelled region is turned into a hint (plane, cylinder, sphere, or free) that the normal fitter must still confirm within the tolerance; a region that fails is handled by the usual detection, so a wrong label costs time, not correctness. Hints are used only on the full mesh, because mesh reduction changes the triangles the labels point at. *Make a hardpoint STL* writes the same triangles back out with the regions the converter found (bytes of the triangles unchanged).

## SCAD → STEP tab
`tostep/plugins/scad2step/scad2step_core.py` (the SCAD2STEP engine) asks OpenSCAD to evaluate the model to its CSG tree text, parses it, and rebuilds each node in OpenCASCADE: primitives become true solids, `linear_extrude` / `rotate_extrude` become swept surfaces, 2D operations become exact faces, and unions, differences and intersections are exact solid booleans. `$fn` below the faceted threshold stays a polygon (so a `$fn=6` nut trap stays hexagonal). `hull()` and `minkowski()` of common shapes are built exactly; text and imported outlines come in as outlines; only things with no exact form (an imported STL, `surface()`) are rendered by OpenSCAD and joined in as flat facets. The result is checked for being one valid closed solid and, optionally, its volume and size are compared with OpenSCAD's own render. `.csg` input skips OpenSCAD. `tostep/plugins/scad2step/bridge.py` is the glue for the web page: the file chooser, OpenSCAD lookup, Customizer fields (turned into `-D` values for the ones you changed) and the live link, which watches the file and the libraries it uses and re-runs the same conversion, queued behind any running job.

## Image → STEP tab
`tostep/plugins/image2step/image2step.py` is the glue; the tracing is the ImageToSketch library (0.10.1), built into `tostep/plugins/image2step/imagetosketch` (refreshed by `tools/sync_imagetosketch.py`) and reached through its `service.py`, the library's front door for programs that embed it. OpenCV does the pixel work. A drawn graphic whose shape runs to the picture's edge is continued a little beyond the edge in the tone of what lies outside it, so the shape closes and is traced; photos are left as they are unless you ask.
1. **Read** the picture (phone rotation, 16-bit scans, transparency) and bring it to a workable size: small pictures are enlarged smoothly, badly blurred ones reduced.
2. **Scale and straighten.** On the *calibration sheet* (0.10.0) OpenCV's ArUco module finds the frame's numbered markers; their known positions give the scale, the tilt and the lens's slight bend from up to 160 corners, a warning when the paper is not flat, and the light across the sheet. The stand's marker, 50 mm above the paper, looks larger than the frame's by distance / (distance − 50), which gives the camera distance for the height correction; page 2's check lines, as measured, take out a printer's stretch. With an *empty-sheet photo* (0.10.1) the two photos are lined up through the markers and compared: what is the same in both (banding, dust) and the part's shadow become paper before step 3. The *scale token* is recognised by its corners (two sharp, one clipped, one rounded) in any of its 8 positions; its four sides are measured to a few hundredths of a pixel, which gives the scale and the tilt of the photo. On the printed sheet a second token in the opposite corner is used with the first, so tilt is measured across the sheet. With the lens's focal length (from the photo's EXIF data, or worked back from a camera distance you type) the camera's position is known, and the picture is straightened in the plane of the part's top (*Part's top above the token*) instead of the plane of the token. The marker sheet, a scan's resolution or a typed number are the other scale sources.
3. **Propose** closed outlines from thresholds at several levels, **verify** each against the real edge (a sharp step counts, a soft shadow ramp does not), and keep, mark as borderline, or reject it.
4. **Vertical sides.** For a thick part seen from one side, the outline facing the camera is the bottom edge and a hole shows its far bottom rim; those stretches are moved to the top edge.
5. **Fit** the fewest lines, arcs, circles, ellipses and splines within tolerance, joined at exact corners.
6. **Write STEP** with OpenCASCADE: each outer outline with the outlines directly inside it becomes a face with holes; thickness 0 writes those faces, a thickness extrudes them into solids. The solid is read back and checked to be closed.

Only accepted (green) outlines go into the file. Simulated photographs with known sizes are the only thing this has been measured on.

**Every colour change (experimental).** Step 3 asks one question: where does the part end and the background begin? With *What to trace → every colour change* it is replaced. Every pixel on a sharp colour step is marked (a pixel inside a gradient moves no more than its surroundings do, so nothing in a gradient is marked); what is left falls apart into areas closed off from one another; neighbours that hardly differ where they meet are joined again; the area round the picture's edge, and anything of its colour, is the background. For each area a two-tone picture is made ("how far is this pixel from this area's colour just here, compared with the neighbour's colour just here") and that goes through the same verify and fit steps as above, so the same rule decides what is real. In the STEP each area is its own face or solid with its own holes, side by side instead of nested. Tried only on pictures drawn by the test code: [docs/research/TRANSITION_TRACING.md](docs/research/TRANSITION_TRACING.md).

## Diagnostic code
`tostep/core/diagcode.py`. When a job ends, the worker sends the report's numbers to the app (a `{"d": ...}` line beside the summary), and the app keeps the settings the job was started with and the performance profile it ran under. Asked for a job's diagnostic (`/api/diag/<job>`), the app packs those into one string, `S2S1-H...-C...-R...-K...`: a header (version, time, job tag, kind, system, state), the conversion settings, the result, an error class if it failed, and a check. Each record is a row of a lookup table of bit fields written in Crockford base32, so the whole thing is about 90 characters and fits a 33 x 33 QR code. The words in the panel are produced by decoding that same string, so the QR and the text cannot disagree. The QR symbol is made by `segno` on the server and drawn by the page; `run_tostep.py diag` reads a code back from text or from a picture (OpenCV's QR detector). The file's name, paths, the log and the error text are never put in the code, and nothing is sent anywhere. Format and reasons: [docs/research/DIAGNOSTIC_CODE.md](docs/research/DIAGNOSTIC_CODE.md).

## Jobs and cancel
Each job (convert, jetwash, SCAD → STEP or Image → STEP) runs in its own worker process (`tostep/core/worker.py`); Cancel kills it. The header meters read system CPU and disk counters through `psutil` (nothing is sent anywhere).

## Profiles, queue and GPU
`tostep/core/perf.py` detects your hardware and turns a profile into a few numbers: thread count (passed to the worker as `OMP_NUM_THREADS` etc. before NumPy loads), process priority, how many jobs may run at once, whether *Second pass* runs both fitters in parallel processes, and whether the optional GPU pack may be used. Jobs wait first-come-first-served for a free slot; a scheduled job waits for its start time first. `tostep/core/gpuinfo.py` lists the graphics cards and decides which PyTorch build each needs; `tostep/core/accel.py` holds the PyTorch version of the v2 fitter's scoring step and is only used when the GPU pack is installed, enabled and a real test on the card has passed (a card PyTorch sees but cannot run, such as a GTX 10-series on the default build, falls back to the processor). See [docs/guide/gpu.md](docs/guide/gpu.md).

## Smooth sketch
For each traced loop: try a circle, then split the loop at sharp corners and at real straight lines, and fit each remaining stretch with an arc or, failing that, a least-squares spline that uses the fewest control points still within the outline tolerance; a loop with no corners or lines is tried as an ellipse, then a closed spline. A stretch counts as a real line when a smooth curve through its surroundings would have to bow away from it far more than the ordinary chords of that loop do (the mesher put no points there because none were needed). Every fit is checked both ways against the traced points, and anything that fails falls back to straight segments.

## Guesstimate mode
Off by default. When on, a freeform patch is accepted if its inside is within the organic tolerance and its outline is still within twice the normal tolerance, so neighbouring faces sew exactly as in the normal mode. Planes, cylinders and spheres are detected and checked with the normal tolerance.

Dense meshes (30,000+ triangles) are reduced first. The mesh is cut into smooth pieces at its sharp edges and each piece is simplified on its own with every outline point locked, so sharp edges and hole rims cannot move; each reduced piece is checked both ways against the original before it is accepted. In the Classic engine every piece keeps a third of the normal tolerance. In the Staged engine, pieces that are exact shapes (flat, cylinder, sphere, lathe, extruded) keep that tight budget and must still sit on their exact surface afterwards, while organic pieces may use a sixth of the organic tolerance; the patch fit then gets what is left of it. Fitted surfaces are measured against the full original mesh, not the reduced one, and the final deviation is always reported against the full original mesh.

## Engines
`classic` (the command line's and the plug-ins' default), `auto` (the Standard preset since 0.10.2: Quad patches when `quadfit.suitable` says the part is a smooth closed organic one and a quad remesher is there, kept if within twice the tolerance; otherwise the Ladder engine), `staged` and `ladder` (experimental, below), `v2` (experimental adaptive NURBS fitter), `quad` (below) and `best` (runs `auto` and v2, keeps the better valid result; `TOSTEP_BEST_FIRST=classic` for the old first pass).

## Ladder engine (experimental)
`tostep/plugins/mesh2step/ladder.py` plus a few switches in the classic core (`Params.ladder`, `route`, `budget_s`, `max_fills`, `max_settle`, `plane_rule`). With it off, the classic code path is unchanged.

1. **Signals** (milliseconds, from the mesh's own data, no rendering): the dihedral-angle histogram (its first valley after the exporter's facet-angle peak becomes the sharp-edge threshold); the area of exact-normal clusters whose border is at least half sharp edges ("sharp-bounded flats"); the area of walls square to a candidate axis; and, about each candidate axis (the biggest normal peaks and the normal-scatter eigenvectors), the share of curved area whose normals lie within 5° of the radial/axial plane (a surface of revolution).
2. **Route.** Prismatic when sharp-bounded flats cover ≥ 30 % and flats + walls ≥ 75 %; lathe when ≥ 85 % of the curved area is a surface of revolution; organic when there are no sharp-bounded flats, no lathe axis and under 2 % of edge length is sharp; otherwise mixed. The route is logged ("Route: …") and reported.
3. **What each route changes.** Prismatic: since 0.10.0 extruded outlines are claimed first (the Staged roughing: on five of seven extruded-profile test parts far fewer faces and a closer fit at the same speed), and when that result is more than twice the tolerance from the mesh `engines.py` runs the plain fitter too and keeps the better; flat-face borders judged by edge length. Lathe: `rough.find_revolves` runs on the whole mesh first and its triangles are left out of the flat-face search; the shapes themselves are then fitted again per smooth component by the Staged roughing (carrying the whole-mesh fit through gave a fragile face on one vase). If the normals say "turned" but no revolve is found (a stepped shaft with a cross hole), the length rule is used so cylinder facets don't pass as flats. Organic: `find_planes` and the cylinder/sphere search are skipped and Guesstimate is on. Mixed: Classic plus Guesstimate.
4. **Caps.** A time budget turns patches still outside tolerance into facets at once (then at most two more passes to re-fit their neighbours); a plate-fill allowance; a cap on settling passes. Patches that are still outside tolerance when passes run out are kept as facets rather than written over tolerance.

The thresholds come from 26 synthetic test meshes in a sandbox (see `docs/research/README.md`); scans were not tested.

## Quad patches engine (experimental)
`tostep/plugins/mesh2step/quadfit.py`. 1. A quad layout of the mesh by QuadriFlow (run as its own program from `tostep/plugins/mesh2step/bin/<system>-<machine>/`) or Instant Meshes (`pynanoinstantmeshes`, split once into all quads). 2. Corners moved onto the mesh; each quad edge a cubic B-spline through seven mesh points along it, all on the same uniform parameters. 3. Each quad a Coons surface from its four curves (`GeomFill_BSplineCurves`), two knots inserted each way. 4. All patches' inner control points solved in one sparse least-squares system: the fit to the nearest mesh points of a grid on each patch, plus a soft condition that the two control points either side of every shared edge lie on a line through it (weight 3), boundary control points held; a patch the fit made worse goes back to its Coons surface. 5. Faces made from the untrimmed surfaces, sewn on their identical edges, measured; the next layout finer by the measured rate of error decrease until within tolerance (at most 6,000 quads, eight layouts, the time ceiling). Taken only for closed meshes with under 5 % sharp-bounded flats, under 0.2 % sharp edge length and not a turned shape; otherwise `engines.py` runs Classic.

## Finishing on a small computer
`perf.py` gives each profile a time ceiling (`budget_s`) and a plate-fill allowance (`max_fills`), passed to the worker as `TOSTEP_BUDGET` / `TOSTEP_MAX_FILLS` and read by `engines.convert` unless set explicitly. Past the ceiling, `_build_surface` stops refining: patches still outside tolerance become facets, at most two more passes re-fit their neighbours, and the solid is assembled. Before the freeform passes on a mesh of 20,000+ triangles (or with `checkpoint="on"`), a checkpoint STEP is assembled from the exact faces with every freeform area as facets and written through a temporary file and an atomic replace; `convert` catches any exception from the fitter (a `MemoryError` from NumPy included — an out-of-memory inside OpenCASCADE itself cannot be caught, which is why the plate filler is skipped when the process already holds 75 % of RAM) and keeps that checkpoint, or writes the faceted solid. `_build_faceted` reduces meshes above 20,000 triangles within half the tolerance first. `build_all` keeps a cache of built-and-checked faces keyed by a region's triangles and the exact state of its boundary chains, and reuses a deep copy on a hit (a reused face object would be mutated by sewing).

## Staged engine (experimental)
`tostep/plugins/mesh2step/rough.py` plus switches inside the classic core (`Params.rough`). It is the classic pipeline with a roughing stage in front and sturdier face building behind. With it off, the classic code path is unchanged.

1. **Lathe shapes.** On a surface of revolution every surface normal, extended to a line, meets the axis. For each smooth component the best axis is found from all triangle normals at once (one 6×6 eigen-problem, re-weighted a few times so parts that don't belong stop counting). The profile is then read off as (distance from axis, position along axis) of every corner, ordered along one cut through the axis, and fitted with the smoothest spline that explains the corners. A profile that is a straight line or a circle centred on the axis is replaced by the exact line or arc, and the face is written as a true cylinder, cone or sphere.
2. **Extruded freeform outlines.** If nearly all normals of a piece are square to one direction, the piece is an extrusion along it; its outline is fitted the same way. The classic cylinder / sphere split still gets the first say: an outline that is just a few flats and rounds stays true planes and cylinders, and the extrusion face is used only where those can't explain the area in a handful of pieces (ovals, spline-shaped walls).
3. **Which triangles belong.** Corners within tolerance, facing the right way, and the triangle's middle and edge points not further from the surface than the mesh's own chord sag allows (a surface that bows away between corners was fitted to too few points and is refused). Triangles that only just miss but touch accepted ones are taken too, and small enclosed islands are filled, so a noisy mesh doesn't pepper the face with pin-holes. Near the axis, where a lathe surface is singular, triangles are left for the patch fitter.
4. **Building the face.** A lathe or extruded region is cut into pieces that don't wrap past the surface's seam (cuts snap to rows of mesh edges where there are any). Each outline edge gets its curve in the surface's own two coordinates computed directly, with its true distance from the surface as the edge tolerance; no general projection or repair pass is involved.
5. **Outlines.** Boundary curves are fitted as in classic (line, arc, spline), but a curve is only used if it stays with the polyline it replaces: chains with a real corner stay polylines, and arcs through too few or unevenly spaced points are refused. Before any face is built, the outline of every swept face is checked for crossings in its own coordinates, and offending chains go back to straight segments.
6. **Write, read back, repair.** The result is written to STEP and read back before it is accepted. A face that doesn't survive the trip, or a round face that can no longer be drawn after it, makes only its own region fall back to facets (or stops round faces being merged into a ring), instead of the whole part falling back.

What it does not do yet: full-ring lathe faces (they come out as three pieces around the axis), tori and blends as named surfaces, splitting a lathe profile into its straight and round parts, and anything better than the classic patch fitter for organic areas.

`tools/bench.py` runs any set of meshes through any engines and prints time, faces by type, regions left as triangles, deviation, file size and peak memory, so changes can be judged by numbers.

## Plug-ins
The FreeCAD workbench and Fusion add-in (`tostep/frontends/freecad`, `tostep/frontends/fusion`) are thin front ends: they export your mesh, call this folder's private Python as a subprocess (`run_tostep.py … --machine`, whose `@@PROGRESS` / `@@DONE` / `@@ERROR` lines are a stable interface) and import the STEP back. They also have an *OpenSCAD → STEP solid* command and an *Export hardpoint STL* command. Both share one bridge file (`tostep/frontends/cad_shared/bridge.py`) and one hardpoint-STL reader (`tostep/core/hstl.py`), added to each at install time.

## Quality presets
`tostep/plugins/mesh2step/presets.py` holds the STL → STEP tab's four presets as plain values for the existing settings (Draft and Quick:
the Ladder engine, Draft with Guesstimate at 0.5 mm, reduction above 50,000 triangles and a 60 s refining cap;
Standard: the Auto engine, since 0.10.2; Fine: Second pass, whose first pass is Auto). The page reads the same table (filled into the page when the app
starts) and the command line's `--preset` sets the same values as defaults, so a preset run and the same settings
made by hand are the same job. Notes: [docs/research/PRESETS.md](docs/research/PRESETS.md).

## Plug-ins (contract 1)
Since 0.11.0-wip every tool is a **plug-in**: a folder under `tostep/plugins/` with a `manifest.toml` (what it is, what it takes, which parameters it has, what each front end shows) and a package with `run(job)`. `tostep/core/registry.py` finds them, `tostep/core/worker.py` runs a job in its own process, the web page and the command line are built from the manifests, and the hand-written FreeCAD and Fusion adapters are checked against them by `tests/test_contract.py`. The old drop-in system (pluggy hooks, a `dropins/` folder, installs from a zip) was dropped; the plug-ins are part of the repository, and a folder named in `TOSTEP_PLUGIN_PATH` can add more. The full description is [ARCHITECTURE.md](ARCHITECTURE.md) and [docs/PLUGIN_CONTRACT.md](docs/PLUGIN_CONTRACT.md).

## What it is not
It does not recover a parametric feature tree (sketches, extrudes, fillets). The result is a solid made of exact surfaces.
