(`## Next (not yet versioned) — fewer round trips to the graphics card
Reported: on an M5 MacBook with the card on, the Halloween cat (Fine preset) ran about twice as fast, "not as fast as expected".
- **Why only 2x:** the card scores only the v2 fitter's shape guesses. The rest of a conversion (building faces, sewing, STEP writing, the first pass of Fine) is OpenCascade, which is processor-only, so the whole job cannot speed up by more than the share the scoring has. In Fine on an Extreme profile the first pass and v2 also run side by side, so the job takes as long as the slower of the two.
- **Changed (all graphics cards, Apple Metal, Nvidia CUDA alike):** each block of guesses used to upload the whole triangle sample again and wait for the card before the next block. The sample is now uploaded once per round, blocks are queued, and the answer is read back once (`accel.score_blocks(sync=False)` + `accel.gather`). Blocks are 1024 guesses instead of 256. Same maths: the 37 GPU tests pass and a whole v2 conversion (PyTorch on the processor) gives the same faces and deviation as NumPy.
- **Not measured on a real card.** The saving is in fixed costs (uploads, waiting), so it should help most on small rounds; the size of it on the M5 is unknown. Press *Test it* and convert the cat again, then send the two times.
- **Low-end machines: the Potato profile reduces big meshes first.** Meshes over 30,000 triangles are reduced (outlines, flat faces and round features kept; the log says so) before converting. Measured on a 2-core Linux machine, 82,000-triangle organic test mesh, Quick engine: 107 s whole, 86 s reduced to 40,000, 45 s reduced to 20,000, 60 s with the Potato profile's 30,000; all closed, valid and inside tolerance. The price: a smooth part can come out as more, smaller faces (25 faces whole, 252 at 20,000 on the same mesh). Only Potato does this; Moderate and Extreme convert at full size. Switch profile, or untick *Protect memory*, to turn it off. `tests/test_potato_ceiling.py`.
- **Paper:** `docs/research/SOLID_EVIDENCE.md` / `.pdf` is now version 1.2: 23 figures and screenshots (before: none), new disclosures D16 (graphics-card scoring) and D17 (triangle ceiling), and updated research list, field report, honesty ledger and citation. D1–D15 are unchanged from version 1.1. `tools/build_paper_pdf.py` now embeds pictures.
- **New, experimental, off by default: the Coons gap filler** (*Advanced → Gap filler*, `--gap-fill`). Where the normal fit misses a freeform patch, a four-sided Coons patch is built on the patch's own outline (grown outwards along the mesh, then trimmed back by the shared outline), with its inside fitted to the mesh as in the Quad patches engine. Choices: plate filler (default, unchanged), Coons then plate, Coons only, none. Measured on the coarse blob and the ridged knob, each filler tried on every hard patch: within the tolerance on 14 of 29 patches against 6 for the plate filler, but about twice as slow per patch; whole parts came out about the same (blob 21 faces instead of 26 at 0.145 against 0.141 mm; knob unchanged; on an 82,000-triangle cat-like figure it was used on 1 of 57 patches and added 165 s). Tests: `tests/test_coons_fill.py`. Paper D18.
- **Per-region hybrid (quad patches plus exact faces): measured, not built.** On a blob cut flat at the bottom, neither quad remesher keeps an open boundary (QuadriFlow's edge ended 3.9 to 8.1 mm off the cut), and QuadriFlow's sharp-edge option left 24 of 56 rim quads crossing the rim (0.379 mm off, not closed). The method and the repair that would make it work are written up as paper D19.
- **Paper version 1.3:** D18 and D19, Figure 3 (the claim ladder) redrawn with what is built today (the old drawing said "not yet" for four-sided patches and Coons fill, though the Quad patches engine already made them), two new figures, the honesty ledger updated.
- **README and guides: more pictures.** The front page now shows the quality presets as the app draws them, the same three parts converted the normal way (Classic) and with roughing first (Staged), and the ghost test model with Guesstimate; the user guides show them where those features are described. All are the paper's own figures.

## 0.11.1-wip — graphics cards: seen is not the same as usable; renamed Twoo STEP CAD Toolbox
- **Renamed** (author's pun on to / two / too): *To STEP CAD Toolbox* → **Twoo STEP CAD Toolbox**, repository `twoo-step-cad-toolbox`, start files renamed to match. The package `tostep`, `TOSTEP_*` variables and CAD ids keep their names on purpose (D14).
Reported: the M5 MacBook showed nothing for graphics acceleration; a Ryzen 5 laptop with built-in Radeon graphics and a GTX 1060 showed the Nvidia card but it could not be selected.
- **Why the M5 showed nothing:** the graphics settings were inside the *Performance* card, which is hidden unless the *Advanced* preset is chosen. There is now an always-visible **Graphics card** box on the Convert tab.
- **Why the GTX 1060 could not be selected:** the tick-box stayed greyed out until a GPU pack was installed, and that pack was plain `pip install torch`. PyPI's current PyTorch has no code for Pascal (GTX 10-series) cards, so even an installed pack saw the card and failed on every operation. Now Pascal / Maxwell / Volta cards get the CUDA 12.6 build (`torch>=2.6,<2.15`, the last line that has it), and a real test, not the word "available", decides whether a card is ready.
- **New:** every card is listed with a tag (Ready / Needs support installed / Installed support does not work / Not usable) and a sentence saying why; one button installs or reinstalls the right build; **Test it** times the card against the processor; **Look again** re-reads the cards. The tick-box is never greyed out.
- **New command:** `tostep gpu` (list), `tostep gpu --install`, `tostep gpu --test`.
- **Safer:** a card that is seen but fails its test is ignored and the conversion runs on the processor, so a card problem cannot fail a conversion. Before this the v2 scoring would have thrown and fallen back mid-job.
- **Found on the first real test (an M5 MacBook):** the box said *Ready*, then *Test it* failed with "Cannot convert a MPS Tensor to float64 dtype as the MPS framework doesn't support float64". Apple's graphics backend has no float64 at all, and the scoring asked the card for a float64 answer. This bug is as old as the GPU pack: on a Mac the card path always threw and quietly fell back to the processor, so no Mac ever used its GPU. Fixed (inputs are converted before moving to the card; the answer is brought back to the processor before widening). *Ready* now requires the real scoring (planes, cylinders and spheres) to run on the card, not just matrix multiplication, which is why the box wrongly said Ready. **Not yet re-tested on the M5** — press *Test it* again; if another operation is missing on Metal, the box will now name it.
- **Honest limits:** the GPU speeds up only the v2 fitter's shape scoring (the *Fine* preset and *Second pass*), nothing else. AMD and Intel graphics are not used (PyTorch has no build this installer can set up for them). The route for GTX 10-series ends when PyTorch 2.14 is no longer installable. Not tested on any real card; see [docs/guide/gpu.md](docs/guide/gpu.md).
- **Tests:** `tests/test_gpu.py` (simulated GTX 1060 + Radeon laptop, M5, silent driver, endpoints, page placement; with PyTorch installed, the real maths against NumPy and the seen-but-cannot-run guard).

## 0.11.0-wip — a new name, a new shape, the same maths
First version of Twoo STEP CAD Toolbox, the long-term-support successor of STL2STEP / EVERYTHING to solid (last version 0.10.3-wip, now frozen).
- **One small core, tools as plug-ins.** Every tool (mesh → STEP, Jetwash, SCAD → STEP, Hardpoint STL, Image → STEP) is a folder with a `manifest.toml` and a `run(job)`; the web page, the command line and the CAD buttons are built from the manifests. Contract 1: [docs/PLUGIN_CONTRACT.md](docs/PLUGIN_CONTRACT.md). Adding a tool: [docs/ADDING_A_PLUGIN.md](docs/ADDING_A_PLUGIN.md).
- **Algorithms untouched.** Files were moved, imports rewritten mechanically. On the test knob the new layout writes a STEP with the same face count (69) and the same byte length (432,037) as 0.10.2.
- **One FreeCAD workbench and one Fusion add-in**, both thin: one shared bridge to the command line, one shared hardpoint reader, put together at install time. Renamed `TOSTEP`; new Fusion add-in id. Hand-written; **never run in the real programs** (LTS gate 4).
- **Golden benchmark** (`tools/golden.py`, `benchmarks/golden.json`): nine small generated parts with written limits; the release gate. It also locks in a known weakness: Classic leaves a 96-sided cylinder as 98 flat faces where Standard and Quick make 3.
- **Tests:** the 0.10.2 suite ported, plus 29 contract tests (manifests, registry, parameter rules, import layers, headers, page assembly, the CAD-command promise), 4 CAD-adapter tests and 3 headless-browser tests. Layers are enforced: plug-ins do not import front ends; a plug-in imports another only if it lists it in `requires`.
- **`pip install .`** works (console command `tostep`); the double-click start files remain the way for most people.
- **CI and release workflows written** (`.github/workflows`): tests + golden on Linux, macOS and Windows, versions recorded; release from `tostep/version.py`, newest four kept. **Not yet run on GitHub.**
- **Added:** `[io] preview` manifest flag (a plug-in whose result is not a mesh, so no 3D preview is offered); a clear error when a plug-in reports success without writing its result file; `TOSTEP_PLUGIN_PATH` for private plug-ins; a bad `--preset` is now a sentence, not a traceback.
- **Fixed on the way over:** Image → STEP's token-sheet error path crashed with a missing `import sys`.
- **Renamed:** environment variables `STL2STEP_*` → `TOSTEP_*`; CAD command ids `STL2STEP_*` → `TOSTEP_*`; start files; the `app/` folder is gone ([docs/MIGRATING_FROM_STL2STEP.md](docs/MIGRATING_FROM_STL2STEP.md)).
- **Removed:** the drop-in plug-in system (replaced by `TOSTEP_PLUGIN_PATH`, decision D4); the stand-alone apps.
- **Still true, said plainly:** nothing has run on a real Mac, Windows PC, FreeCAD or Fusion; dependencies are version ranges, not pins; Image → STEP is experimental; Quad patches were tried on five synthetic shapes. See [docs/KNOWN_LIMITATIONS.md](docs/KNOWN_LIMITATIONS.md) and the gates in [LTS_POLICY.md](LTS_POLICY.md).
